## Публичный API

Официальный API известен как интерфейс чтения/экспорта, с методами
`getprojectslist`, `getprojectinfo`, `getpageslist`, `getpage`, `getpagefull`,
`getpageexport`, `getpagefullexport`. Документация указывает base URL `https://api.tildacdn.info`, метод GET,
JSON, publickey/secretkey, тариф Business и лимит 150 запросов в час.
Клиент к ним пока не реализован. Ни один запрос с ключом не выполнялся.

| Операция | Оценка публичного контракта |
| --- | --- |
| Список проектов/страниц, получение HTML | Чтение/экспорт предусмотрены |
| Создать страницу | В опубликованном списке методов отсутствует |
| Добавить T123/HTML-блок | В опубликованном списке методов отсутствует |
| Отредактировать содержимое/метаданные | В опубликованном списке методов отсутствует |
| Опубликовать страницу на Tilda | В опубликованном списке методов отсутствует |

Получить HTML не значит записать HTML обратно. Экспорт страницы не создаёт
новую страницу в Tilda. Пока Tilda не подтвердит иной поддерживаемый интерфейс,
автоматическую публикацию новых страниц **через официальный публичный API
считать недоступной**. Несуществующие createpage/updatepage/publishpage
методы не используются и не предлагаются.

## Реальные варианты

1. **Tilda-редактор вручную.** Подготовить статью/HTML в облаке, редактор создаёт
   страницу из шаблона, вставляет контент и публикует. Надёжный старт с проверкой
   человеком; полностью автоматическим процессом не является.
2. **Внешний CMS/статический хостинг статей.** Tilda сохраняет основной сайт,
   статьи размещаются, например, на согласованном поддомене. Облачный CI
   генерирует и развёртывает HTML через поддерживаемый API хостинга. Это
   рекомендуемый вариант полной автоматизации без личного компьютера.
   Это отдельный хостинг, не создание страниц внутри Tilda. Для сохранения
   `/articles/...` на основном домене понадобится контролируемый reverse proxy,
   отдельный аудит маршрутизации, SEO и условий Tilda; обещать его без проверки нельзя.
3. **Playwright в облачном runner через интерфейс Tilda.** Технически браузер
   работает в облаке, личный компьютер не нужен. Но это не официальный write API:
   изменения UI, MFA, CAPTCHA и сессий могут остановить процесс. Нужны проверка
   условий использования и разрешение владельца. Не обходить MFA/CAPTCHA.
   Для требования «именно страница внутри Tilda» это кандидат на отдельный
   тестовый прототип с ручным подтверждением и сверкой результата.
4. **Экспорт Tilda на свой хостинг.** Экспорт/API позволяют использовать Tilda
   как источник дизайна и собранных страниц, а публикацию выполнять своим
   deploy-процессом. Не добавляет новые страницы в редактор Tilda; требования
   тарифа, лицензии, формы и другие сервисы проверить отдельно.

Импорт HTML-блока и встроенные формы/входящие webhooks не являются API создания
страниц. Если рассматривать Feeds или партнёрский сервис, сначала получить
официальное описание поддерживаемого write-интерфейса; его наличие не установлено.

## Вывод

Облачное выполнение без включённого компьютера возможно. Без браузера вообще —
через собственный CMS/хостинг с API. Для новых страниц внутри Tilda поддерживаемый
публичный путь записи пока не установлен: сначала запросить подтверждение Tilda,
затем выбрать ручную публикацию либо отдельный облачный browser-прототип.

Источники для повторной проверки: [Tilda API](https://help-ru.tilda.cc/api),
[English API](https://help.tilda.cc/api), [экспорт](https://help-ru.tilda.cc/export),
[GitHub schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
API, HTML и SEO-справка прочитаны при повторном исследовании. Экспорт и GitHub
schedule отдельно не перечитывались. Возможности конкретного аккаунта не проверены.
Облачный браузер исследован отдельно в [browser-prototype.md](browser-prototype.md).
Внешний хостинг исключён пользователем из текущего направления разработки;
перечисленные выше альтернативы оставлены как история первоначального аудита.
